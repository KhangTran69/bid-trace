# BidTrace Implementation Plan

> **For agentic workers:** Implement the tasks in order in this repository. Khang authorized execution. Use the existing team consultation findings below; do not add scope without evidence.

**Goal:** Deliver a local interview demo that imports source-linked bid line items, supports correction and approval with audit history, and exports approved data only.

**Architecture:** FastAPI with server-rendered Jinja pages and SQLAlchemy/Alembic on PostgreSQL. Deterministic parsers handle one documented text-PDF layout plus CSV/XLSX; uploaded files are stored locally by SHA-256.

**Tech Stack:** Python 3.12+, FastAPI, SQLAlchemy 2, Alembic, psycopg 3, PostgreSQL 16, Jinja2, pypdf, openpyxl, pytest, Docker Compose.

**Spec:** docs/superpowers/specs/2026-11-04-bidtrace-design.md

## Global Constraints

- Synthetic fixtures only; no real bids, personal data, credentials, or customer content.
- One reviewer account; local loopback only; no production or cloud deployment.
- Upload limit 10 MiB; accept only .pdf, .csv, and .xlsx.
- Keep imports atomic and idempotent by content SHA-256.
- Keep query-plan and backup/restore demonstrations on temporary data or a scratch database.

## Review Focus

- Duplicate concurrent uploads race on the unique content hash; only one document/item set may persist.
- Malformed or corrupt files must leave no partial database rows or newly stored upload.
- CSV/XLSX values may be blank, non-finite, negative, or formulas; reject unsupported/invalid values clearly.
- Source file names may contain path traversal or HTML/CSV injection strings; never use them as paths or active markup.
- A stale correction may race with another reviewer action; reject it with a conflict instead of overwriting the newer value.

### Task 4: Review, audit, and approval

**Interface:** review_line_item(session, *, item_id, expected_version, values, action: Literal["save", "approve"], actor="demo-reviewer"); stale versions raise a domain conflict. Saving persists corrections and marks the row corrected. Approving persists the submitted values and marks that row approved. When the final row is approved, the bid becomes approved in the same transaction.
